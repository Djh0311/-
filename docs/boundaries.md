# 产品与安全边界

## 默认边界

项目只接受本地、合成、脱值、可完整校验的输入。没有新用户授权和新资格证据时，所有真实能力都视为关闭。

## 禁止输入与副作用

- 真实请求、响应、流量、Cookie、凭据、会话或私人消息；
- 历史 raw capture 正文或从中投影业务值；
- 网络访问、浏览器/微信 UI、系统代理、CA、keychain、管理员配置；
- 原始 payload 落盘、值哈希、自由键透传、敏感错误回显；
- 跨来源、跨时间或跨 observation 补值；
- 未冻结的目录、glob、可变输入集合或自动重试。

## 进入真实能力前必须重新裁决

至少需要：明确来源所有权与用途、冻结的 value-free shape、family/version、同观察绑定、隐私销毁规则、能力清单、失败停止行为、一次性输入锁和用户明确授权。任一项缺失，`LIVE_CAPTURE_LATCH` 与 `EXECUTION_LATCH` 继续保持 `CLOSED`。

## 计划与执行的区别

[后续计划](harness/plan.md)以真实网络响应和公开业务结果为目标；上述默认边界描述离线安全基础的默认状态（无显式授权时所有真实能力关闭），不把离线验证作为产品终点。任务进展（2026-10-16）：P25–P28 已 accepted 并退场、P29/P31 active/incomplete，当前采集已停、两 latch=CLOSED；真实窗口均在既有“按窗口显式授权”下进行。任务写面及验收条件本身不构成新的执行授权。

后续由开发者承担接口识别、字段映射和配置准备；用户确认目标及必须本人决定或操作的事项。每次真实步骤的范围、预算和停止行为须明确，旧收据和计划通过不能代替。多页结果可以汇总各自完整的记录，但不得跨观察拼字段；“字段尽量多”也不包含账户、凭据、私人位置或订单信息。
