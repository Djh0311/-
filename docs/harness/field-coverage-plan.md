## 字段登记格式

每个已识别字段至少登记：稳定字段名、业务含义、店铺/商品/SKU/优惠/配送归属、单位或枚举、是否核心字段、适用条件、明确的来源结构标签、适配与导出状态、未完成原因及对应任务。

计划与仓库只保留无业务值的字段定义和状态；真实公开业务值仅进入获准的受控结果集。不得在登记表中保存原始响应、URL、headers、Cookie、会话、值哈希或自由错误。

| 字段状态 | 使用条件 |
| --- | --- |
| 已确认可得、已导出 | 当次获准来源确实提供，含义明确，解析与导出均通过 |
| 已确认可得、未适配 | 来源确实提供但实现尚未完成；仍计入开发缺口 |
| 来源未提供 | 已检查该次适用输入，没有该字段；不代表平台永远不提供 |
| 待确认 | 还未观察、含义/单位/归属未确认或来源版本不明 |
| 不适用 | 有明确业务条件证明该字段对该记录不适用 |
| 解析失败/被拒绝 | 固定原因码说明；不能伪装成来源未提供 |

每个结果字段也要保留 presence 与 absence_reason 或等价的明确状态。空字符串、0、未知、未提供和不适用不能互换。

## 覆盖与完成口径

- 商品覆盖：区分商品数、SKU 数、分类数和页面数，报告未访问/失败/未确认的范围。
- 字段覆盖：针对本次已确认可得且适用的字段报告应导出与实际导出情况；未提供、不适用、未知、解析失败分别计数。
- 不知道总商品数或所有可能字段时，不编造全店或全平台百分比。只有分类/分页终止与范围证据足够时才能声明完整。
- 核心身份、名称、价格或关联不成立的记录不能验收为正确记录；扩展字段缺失须附明确原因，不跨观察补齐。
- 需求范围内已确认可得字段没有遗留未适配项、没有未解决的错配、输出与来源核对一致，才可宣称对应字段组完成。
- 来源无法证明、读取受限或未出现的能力标 UNKNOWN/未验证；缩小最终交付范围需要显式说明，不能静默删项。
